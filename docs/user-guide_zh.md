## 核心概念

Minta 存储**记忆对象**——关于你、你的工作、你的偏好、你的决策的结构化事实。这些对象会喂给你的 AI agent，让它"记住"你是谁、怎么工作。

### 7 个记忆槽位

你的记忆被组织进 7 个槽位。把每个槽位想象成你个人记忆柜里的一个抽屉：

| 槽位 | 放什么 | 示例 |
|------|--------|------|
| **Persona（人设）** | 你是谁、角色、背景 | "全栈开发者，5 年经验，偏好 TypeScript" |
| **Preferences（偏好）** | 你喜欢怎么做事 | "用 2 空格缩进，优先 async/await 而非 Promise" |
| **Knowledge（知识）** | 技术事实、项目上下文 | "我们 API 用 JWT，24h 过期，存 httpOnly cookie" |
| **Counter Examples（反例）** | 要避免的错误、教训 | "测试断言别用 Date.now()，用 vi.setSystemTime()" |
| **Skills（技能）** | 可复用工作流 | 代码审查清单、部署步骤、bug 排查流程 |
| **Pending（待处理）** | 等待审查的条目 | 对话中的反馈、尚未处理的发现 |
| **Rules（规则）** | 硬约束、始终生效的规则 | "绝不把 .env 文件提交到 git" |

### 记忆对象类型

每个对象有一个 **type** 告诉 Minta 这是哪种记忆：

- **`preference`** — 工作习惯（编辑器设置、代码风格、沟通偏好）
- **`workflow`** — 可复用流程（部署步骤、代码审查清单）
- **`project_context`** — 项目事实（架构决策、技术栈、领域知识）
- **`decision_criteria`** — 决策依据（优先级、约束、经验法则）
- **`lesson_learned`** — 吃过的亏（修过的 bug、踩过的坑）
- **`writing_style`** — 文风和语气（正式程度、术语偏好、受众定位）
- **`rule`** — AI 必须遵守的硬规则
- **`ai_brief`** — 每次会话前给 AI 的上下文
- **`work_profile`** — 职业身份和当前关注点

## 仪表盘概览

打开 `http://localhost:8772`，进入主仪表盘：

```
┌─────────────────────────────────────────────────────┐
│  🔍 搜索框           [收件箱(3)]  [⚙ 设置]          │
│─────────────────────────────────────────────────────│
│  记忆健康分: 85/100                                   │
│  ████████████████░░░░                                │
│─────────────────────────────────────────────────────│
│  📋 全部记忆   📥 收件箱   📦 打包   🔧 技能         │
│─────────────────────────────────────────────────────│
│  [类型过滤器]                                        │
│  ┌─────────────────────────────────────────────┐    │
│  │ 记忆卡片：标题、类型、置信度……               │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

### 导航标签

- **全部记忆** — 浏览、过滤、管理你的记忆对象
- **收件箱** — 审查待处理的纠正、反例、扫描发现
- **上下文包** — 查看 7 个槽位，生成 AI 注入用的 Context Pack
- **技能** — 浏览和管理可复用技能模板
- **Story（故事页）** (`/story`) — 互动演示，虚拟角色的记忆旅程

### 记忆健康分数

仪表盘显示**健康分数（0–100）**，由四个维度计算：

| 指标 | 衡量什么 | 指标差意味着 |
|------|---------|------------|
| **D_S**（陈旧度） | 有多少记忆超过 30 天未使用 | 高 → 知识过时 |
| **D_R**（冗余度） | 重复或接近重复的记忆 | 高 → 知识碎片化 |
| **D_C**（冲突度） | 互相矛盾的记忆 | 高 → AI 不可靠 |
| **D_V**（范式违规） | 格式不完整或异常条目 | 高 → 数据质量问题 |

高于 80 分是健康的。低于 60 分，建议运行一次记忆扫描。

## 管理记忆对象

### 创建记忆对象

1. 点击 **+ 新建记忆**
2. 填写：
   - **标题**（必填）— 简短描述性名称
   - **类型**（必填）— 从 9 种类型中选择
   - **摘要**（可选）— 一句话说明
   - **正文**（可选）— 完整细节、示例、上下文
   - **标签**（可选）— 搜索关键词，如 `["react", "前端", "测试"]`
   - **置信度**（1–5）— 你有多确定这仍然适用
3. 点击**保存**

> 💡 **提示：** 哪怕只有一句话加几个好标签也有用。不需要写论文——AI agent 会自动组合多条记忆。

### 编辑记忆

点击任意记忆卡片进入详情页，可以：

- 修改标题、摘要、正文、标签
- 更改类型或置信度
- 切换**公开**以分享到社区
- 上传**封面图**（截图类记忆尤其有用）

### 删除记忆

打开详情页 → 点击**删除**。这是永久操作，不可撤销。

### 过滤记忆

顶部有类型过滤按钮，可以只看：
- 偏好
- 工作流
- 项目上下文
- 经验教训
- 规则
- ……或任意自定义类型

结合搜索框实现精细化过滤。

## 收件箱 — 你的记忆审查队列

**收件箱**是 Minta 存放待你审查事项的地方。把它想象成你记忆的通知中心。

### 什么会进收件箱？

1. **自动检测的问题** — 记忆健康扫描发现（陈旧、冲突、重复）
2. **反例** — 你纠正 AI 时自动捕获的教训
3. **手动添加** — 你从仪表盘添加的条目
4. **Autopilot 建议** — 对话后的自动分析建议

### 审查收件箱条目

对每条收件箱条目，你有三个选择：

| 操作 | 什么效果 |
|------|---------|
| **确认** | 接受建议，转为记忆对象 |
| **丢弃** | 忽略（适合误报） |
| **跳过** | 留在收件箱以后处理 |

确认时，你选择它变成什么类型的记忆。例如：
- 一条陈旧记忆检测 → 确认为 `lesson_learned`
- 两条规则冲突 → 确认修正后的版本为 `rule`

### 收件箱状态

- **`pending`** — 等待你审查（默认）
- **`archived`** — 已审查处理完毕

## 记忆健康扫描

Minta 每 24 小时自动扫描你的记忆健康。你也可以随时手动触发。

### 扫描器检测什么

| 扫描类型 | 发现什么 | 示例 |
|---------|---------|------|
| **陈旧度** | 超过 30 天未使用的记忆 | 你已经换成 hooks 了还留着 "React class component" |
| **冗余度** | 接近重复的记忆（80%+ 相似） | 两条偏好都在说 "用 2 空格缩进" |
| **碎片化** | 一个标签下记忆太多 | `#debugging` 标签下有 15 条记忆 |
| **冲突** | 互相矛盾的建议 | "Always use async/await" vs "Use .then() for Promise chains" |
| **范式** | 不完整或异常的条目 | 正文为空、置信度极低的记忆 |

### 手动运行扫描

1. 进入 **Lifecycle** 标签
2. 点击 **运行记忆健康扫描**
3. 等待 ~2–5 秒（取决于记忆数量）
4. 在**收件箱**中查看发现
5. 逐条确认或丢弃

### 配置自动扫描

```bash
# 查看当前自动扫描状态
curl http://localhost:8772/api/lifecycle/auto-scan/status

# 改为每 6 小时扫描一次
curl -X POST "http://localhost:8772/api/lifecycle/auto-scan/interval?hours=6"

# 关闭自动扫描
curl -X POST "http://localhost:8772/api/lifecycle/auto-scan/toggle?enabled=false"
```

> 💡 **提示：** 日常使用默认的 24h 扫描即可。高频使用时可以调到 1–2 小时。

## 语义搜索

Minta 使用基于 embedding 的搜索，意味着你可以按**语义**而非关键词搜索。

### 如何搜索

1. 在搜索框输入自然语言查询
2. Minta 按语义相似度排序结果
3. 结果以**渐进披露**方式展示：
   - **紧凑** — 标题 + 类型（快速浏览）
   - **完整** — 标题 + 摘要 + 标签（详细查看）
   - **打包** — 完整内容（深度阅读）

### 搜索技巧

```
✅ "React 里怎么处理错误？"            → 找到错误处理模式
✅ "我的编码习惯"                    → 找到所有 preference 类型记忆
✅ "数据库连接怎么配"                 → 找到相关项目上下文
❌ "eror handlng"                     → 也能用，但语句通顺效果更好
```

> 💡 Minta 搜索标题、摘要、标签和语义 embedding。不需要完美的关键词。

## 上下文包（AI 注入）

**Context Pack** 是你 7 个记忆槽位的编译快照，格式化为可直接注入 AI agent prompt 的文本。

### 生成上下文包

1. 进入 **Packs** 标签
2. 检查你的 7 个槽位——更新需要改的
3. 点击**生成 Pack**
4. 选择场景：`auto`、`coding`、`writing`、`research`、`general`
5. 复制生成的文本

### 配合 Claude Code 使用

```bash
# 方式 1：通过 MCP（自动）
# 在 Claude Code MCP 设置中配置 —— 参见 docs/mcp-integration.md

# 方式 2：手动复制粘贴
# 生成 Pack，复制，粘贴到对话开头
```

### 各场景包含什么

| 场景 | 重点槽位 | 适合 |
|------|---------|------|
| `coding` | Preferences, Knowledge, Rules, Lessons | 编程会话 |
| `writing` | Writing Style, Persona, Preferences | 内容创作 |
| `research` | Knowledge, Project Context, Decision Criteria | 研究分析 |
| `general` | 全部 7 个槽位（均衡） | 任意对话 |
| `auto` | 从当前上下文自动检测 | 默认（推荐） |

## 技能库

技能是可复用的工作流、检查清单和流程模板。可以私有或分享到社区。

### 创建技能

1. 进入 **Skills** 标签
2. 点击 **+ 新建技能**
3. 填写：
   - **名称** — 简短标识
   - **分组** — 类别（如 `code-review`、`deployment`、`debugging`）
   - **内容** — 实际步骤/模板
4. 点击**保存**

### 使用技能

技能会自动出现在你 Context Pack 的 **Skills** 槽位中。生成编程会话的 Pack 时，你的代码审查清单技能会自动包含进去。

### 社区技能

浏览其他 Minta 用户公开分享的技能。点击任意技能的**分享**按钮即可贡献到社区。

## 社区分享

你可以将任意记忆对象标记为**公开**，分享到 Minta 社区。

### 分享如何运作

1. 编辑一个记忆对象
2. 将**公开**切换为 ON
3. 对象出现在**社区动态**
4. 其他用户可以：
   - 查看该对象
   - 留下嵌套评论
   - 从公共池抽卡获取灵感

### 内容审核

评论自动经内容过滤。有速率限制（每用户每 60 秒最多 5 条评论）。

## 专家系统（临床决策支持）

Minta 内置了领域专家推理引擎。当前支持临床决策规则。

### 可用领域

| 领域 | 规则依据 | 评估什么 |
|------|---------|---------|
| `ankle_injury` | Ottawa 踝关节规则（Stiell 1992, JAMA） | 是否需要踝关节 X 光 |
| `knee_injury` | Ottawa 膝关节规则（Stiell 1996, JAMA） | 是否需要膝关节 X 光 |
| `cervical_spine_injury` | 加拿大颈椎规则（Stiell 2001, JAMA） | 是否需要颈椎影像 |

### 使用专家系统

1. 进入 **Expert** 标签或打开 Chat
2. 选择领域（如 `ankle_injury`）
3. 描述患者症状
4. 系统应用临床决策规则
5. 得到带置信度的推荐

### Chat 界面

`/api/chat` 端点自动从消息中检测领域：

```
你："患者扭伤脚踝，外踝压痛"
Minta："领域：ankle_injury。应用 Ottawa Ankle Rules……
       规则 A（外踝压痛）：阳性
       → 建议：需要 X 光。置信度：0.92"
```

> ⚠️ **声明：** 专家系统仅供教育和决策辅助用途，不替代临床判断。

## 账户与隐私

### 账户管理

- **注册** — 首次启动时创建用户名和密码
- **个人资料** — 在 `/api/auth/me` 更新头像、邮箱
- **邮箱验证** — 可选；需要配置 SMTP（见[配置指南](configuration.md)）

### API 密钥

用于程序化访问（MCP 工具、脚本）：

1. 进入设置 → **API 密钥**
2. 点击 **创建新密钥**
3. 复制密钥（仅显示一次！）
4. 在请求中使用：`X-API-Key: minta_……`

### 数据隐私

- 所有数据**本地存储**，不离开你的机器
- **导出**全部数据：`GET /api/user/export-data`
- **删除**全部数据：`DELETE /api/user/delete-data`
- 敏感数据（API 密钥、密码、邮箱）**自动过滤**，不会存入记忆内容
- 漏洞报告见 [SECURITY.md](../../SECURITY.md)

## 故障排除

### "Minta 启动不了"

```bash
# 检查 8772 端口是否被占用
netstat -ano | grep 8772

# 杀掉旧进程重试
minta stop
minta start

# 查看日志
cat logs/minta-$(date +%Y-%m-%d).log
```

### "启动时出现 SMTP 警告"

这是正常的。SMTP 仅用于邮箱验证。如果不需要邮箱验证，忽略即可。需要配置见[配置指南](configuration.md)。

### "登录提示 'not authenticated'"

1. 确认已先注册
2. 检查用户名和密码
3. JWT token 24 小时过期——重新登录

### "记忆对象显示 0 条"

1. 创建过记忆对象吗？试试运行 `minta start` → 打开 `/story` 填充演示数据
2. 检查类型过滤器是否隐藏了所有内容
3. 运行 `python -c "from server.config import engine, Base; Base.metadata.create_all(bind=engine)"` 确保表已创建

### "搜索无结果"

1. 确保有带内容的记忆对象
2. 语义搜索需要 embedding 服务可用
3. 试试更简单的查询，或先不搜索直接浏览

### "端口 18721 已被占用"

MCP HTTP 服务默认用 18721 端口。如果被占用：
```bash
MCP_HTTP_PORT=18722 minta start
```

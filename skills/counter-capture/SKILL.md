# 反例收集技能

## 自动启动服务器

**在任何反例操作前**，检查端口 18720 是否已占用。若未占用，后台启动服务器：

```bash
python "C:\Users\Lenovo\.claude\projects\C--Users-Lenovo\memory\counter_server.py" --no-browser &
```

若已占用，跳过启动直接继续。

检查方法：
```bash
python -c "import socket; s=socket.socket(); s.settimeout(0.3); r=s.connect_ex(('127.0.0.1',18720)); s.close(); print('running' if r==0 else 'stopped')"
```

## 触发方式

- **自动**: 对话中检测到用户纠正语气 → 自动写入收件箱
- `/反例 <描述>`: 手动登记，追加到 counter-inbox.md
- `/反例` (无参数): 交互式引导录入

## 自动捕获规则

当用户消息包含以下信号时，自动把当前上下文中的错误行为写入收件箱：

| 信号 | 关键词 | 置信度 |
|------|--------|--------|
| 直接否定 | "错了""不对""不是吧""搞错了""有问题""不行" | 0.9 |
| 反问纠正 | "为什么不""你怎么不""应该先""要先""怎么不先" | 0.8 |
| 对比纠正 | "我要的是X不是Y""应该是X""不是说好了" | 0.9 |
| 重做指令 | "重新""再来""改一下""重写""改回来" | 0.7 |
| 通用不满 | "不满意""不好""别这样""烦""算了" | 0.5 |

**执行时**:
1. 从最近 2-3 轮对话中提取：
   - 错误行为: Claude 做了什么导致纠正
   - 正确做法: 用户期望的正确行为
   - 原因: 为什么正确做法更好（可从上下文推断）
2. 追加一行到 `memory/.remember/counter-inbox.md`，格式：
   ```
   - [YYYY-MM-DD HH:MM] [conf:X.X] [status:pending] 错误描述 → 正确做法 → 原因 #标签
   ```
3. 标签从以下自动选择: `#工具使用` `#沟通风格` `#代码规范` `#宪章违规` `#文件操作` `#前端设计`
4. 回复末尾简短告知: `📥 已自动登记`
5. 不打断对话流

## 手动登记 `/反例 <描述>`

直接将 `<描述>` 写入收件箱，格式同上。自动推断标签。置信度默认 0.9。
告知用户: `📥 已登记到收件箱`

## 交互引导 `/反例` (无参数)

反问用户三个问题：
1. Claude 做错了什么？
2. 正确的做法应该是什么？
3. 为什么？（可选）

收集后写入收件箱，置信度默认 0.9。

## 收件箱位置

`memory/.remember/counter-inbox.md`

- `/反例面板` — 打开知识库管理面板（带服务器）
- `/反例整理` — 命令行批量归档到 feedback_counter-examples.md
